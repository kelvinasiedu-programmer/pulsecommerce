Analytics portfolio

Five questions about an ecommerce business,
answered end to end.

A synthetic but statistically realistic dataset of 25,000 customers and 95,000 orders, modelled through a layered SQL warehouse and published as interactive Tableau dashboards. Three of the five analyses live here. The forecasting and churn models live in the Python app.

How it's built

The dashboards are the last step, not the whole project. Everything upstream is reproducible from a single command.

  1. 1

    Generate

    A seeded generator produces users, products, orders and clickstream events with weekly and annual seasonality, a Q4 holiday lift, device-by-channel conversion asymmetry, and a Zipf-Mandelbrot repeat-buyer skew.

  2. 2

    Model

    DuckDB warehouse with staging, marts and metrics layers kept in separate SQL files, laid out the way a dbt project would be. One definition of revenue, referenced everywhere.

  3. 3

    Analyse

    Five Python layers on top of the warehouse: KPIs, funnel, demand forecast (seasonal-naive vs Holt-Winters vs XGBoost), churn (logistic + XGBoost on RFM features) and a simulated A/B readout with guardrails.

  4. 4

    Publish

    pulsecommerce tableau flattens the warehouse into tidy CSVs at a grain Tableau can still aggregate, so the workbooks stay interactive rather than rendering numbers Python already decided.
